# Plan F05 + F06 — Content system: schemas, loader, gates, provenance

## Approach
- `src/lib/content/schema.ts`: Zod schemas for every entity in the PRD data model.
- `src/lib/content/load.ts`: reads `content/` (YAML + Markdown frontmatter) into one typed `Corpus`. It's pure and synchronous, so Astro, scripts and Vitest all share it.
- `src/lib/content/gates.ts`: `runGates(corpus) → GateError[]`. Every F05/F06 rule is one named gate. `scripts/validate-content.ts` prints errors and exits 1, and `npm run build` runs it first.
- **Staleness:** each verification log stores `claimsHash` (sha256 of the subject's claim texts + citations). A mismatch means the log is stale.
- **Source classes:** `primary` | `secondary` (with `scholarly: boolean`) | `tertiary`. Tertiary never counts. A claim needs ≥ 2 distinct counting (primary/secondary) sources, at least one of them a `scholarly: true` secondary.
- **Strict schemas:** every Zod object is strict, so YAML flow-map comma truncation fails loudly (a real bug caught during authoring).
- **Archive links:** derived as `https://web.archive.org/web/2026/{url}` (resolves to the nearest snapshot). They aren't stored.
- **Assets (F06):** licence ∈ {PD, PDM, CC0, CC-BY}. `kind: generated` plates are our own renders. A local `file` is optional, and its presence switches the story image from the generated plate to the scan.
- **Corrections:** `buildCorrectionUrl({discoveryId, claimId})` → prefilled GitHub issue URL, with a mailto fallback. `content/corrections.yaml` holds the public log.
